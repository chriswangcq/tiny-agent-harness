## 1. Skill Discovery & Store (Medium)

**Files**: `src/skill/discovery.ts`, `src/skill/store.ts`

**Current violation**:
- Directly calls `fs.existsSync`, `fs.readFileSync`, `fs.mkdirSync`
- `skillsDir` / `skillRunsDir` derived implicitly via `resolveStateDir()` which reads `process.env.TAH_STATE_DIR`

**Fix direction**:
- Constructor accepts explicit `skillsDir: string` and `skillRunsDir: string`
- CLI layer resolves env → dirs, passes them in
- Tests can use tmp dirs without mocking fs

## 2. Transcript Store / IM Transport / Session Store (Medium)

**Files**: `src/transcript/store.ts`, `src/im/transport.ts`, `src/tui/transcript-reader.ts`, `src/run/session-store.ts`

**Current violation**:
- Direct `fs.readFileSync`, `fs.writeFileSync`, `fs.mkdirSync` in core modules
- No injected storage adapter interface

**Fix direction**:
- Define `TranscriptStore` / `MessageStore` / `SessionStore` interfaces
- File-backed impl lives in adapter layer
- Fake impl for testing

## 3. Code-Intel implicit env/fs (Low)

**Files**: `src/code-intel/config.ts`, `src/code-intel/workspace.ts`, `src/code-intel/lsp/typescript.ts`

**Current violation**:
- `config.ts:71`: reads `process.env.CODEQ_TYPESCRIPT_SERVER_COMMAND`
- `workspace.ts:40`: reads `process.env.PATH`
- `typescript.ts:208`: `fs.readFileSync` on arbitrary paths

**Fix direction**:
- Accept explicit config object (server command, PATH)
- Inject `fileReader: (path: string) => string` for file reads
